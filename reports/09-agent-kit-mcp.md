## Scope

Phase 9 adds a bounded Agent Kit/MCP adapter without changing the frozen IRP-1 protocol schema, the Phase-2 receipt kernel, deterministic policy semantics, three public proof cases, or the published Phase-8 release tag.

The official `hashgraph/hedera-agent-kit-js` repository was re-read before implementation. The integration pins `@hashgraph/hedera-agent-kit` 4.1.0, `@hashgraph/hedera-agent-kit-mcp` 1.1.0, `@modelcontextprotocol/sdk` 1.30.0 and `@hiero-ledger/sdk` 2.87.0.

## Implemented surface

`integrations/hedera-agent-kit/` contains:

- a v4 `Plugin` exposing three IRP-1 `BaseTool` tools;
- `Irp1ToolAllowlistPolicy`, applying fail-closed to every method via `relevantTools = ['*']`;
- `buildIrp1AgentKitConfiguration()` with `AgentMode.RETURN_BYTES` as the default human-in-the-loop transaction mode;
- `createIrp1McpToolkit()` using the official Hedera Agent Kit MCP toolkit and the same bounded configuration;
- exact dependency lockfile and hardened transitive overrides;
- seven integration tests;
- reproduction documentation.

The three tool methods are:

1. `irp1_verify_local_bundle`
2. `irp1_verify_network_evidence`
3. `irp1_compare_action_manifests`

No autonomous transaction-signing or broadcast tool is introduced by the IRP-1 plugin itself.

## Security / control invariants

- Unknown tool methods are blocked by the explicit allowlist policy.
- Transaction-capable tools added by a future caller default to `RETURN_BYTES`, not autonomous execution.
- Adding an external plugin does not implicitly authorize its tools; methods must also be explicitly allowlisted.
- The adapter reuses the repository's canonical verifier and correspondence implementation instead of forking protocol logic.
- The MCP surface is generated by Agent Kit discovery from the same configuration.
- Integration tests require no private key and submit no Hedera transaction.
- No private key, `.env` value, account secret, customer/personal data or private evidence is introduced.
